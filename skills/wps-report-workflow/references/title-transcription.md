# 正式名称：转录而非写作

适用：附件正式文件名、批复/函/通知标题等要求复刻的原文。不用于用户明确授权改写的正文。目标是“识别＋复制”，不是增加一轮自由生成或全册重审。

## 生产路径

1. **选原件。** 用实际材料ID及原PDF可见页/用户新增原件定位完整标题；模板只提供格式。最新Word决定保留范围，不意味着其中OCR文字或旧外抬头已经正确。用户明确指定的改名另记原指令，不自行猜其意图。
2. **提取原文。** 电子文字能提取就复制；扫描标题只对标题区域OCR，结果对照原图逐字核实，必要时看上下行。保留准确字词、单位、年份、工程类别、书名号及“批复/意见/函”等文种。OCR是候选文字，漏字、模糊或冲突待核，不按常见措辞补全。不要给正式名称润色、概括、纠错或“统一用语”。
3. **核实后锁定。** 已有业务材料清单内记录material_id、原件路径/指纹/页与标题位置、source_title、核实依据。正式名称和目录简称分字段。转换稿标题只能用作检索线索，不直接复制为已核实值；题名和正文用语冲突也不擅自改题名。
4. **直接填充。** 程序读取source_title，在前面加附件编号；只改字体、字号、段落、换行、位置，不重新调用模型生成标题字符串。目录短名按范本/用户约定另存，绝不反向覆盖正式抬头。
5. **零文字差异检查。** 从实际输出DOCX对应段落读回文字，去附件编号及空白后与锁定原文逐字一致；不做语义相似度匹配，不忽略标点或同义词，不为排版删字。差异直接阻止该项放行；只对差异/疑难回看原图，再按既有要求检变化页和相邻排版。

需要人工/模型判断的是辨认原件和处理歧义，不是重新组织已经确定的名称。来源和核实文字未变的后续任务可以复用锁定记录；任何来源/名称/对应关系变化使这项核实失效，重新核对相关项即可。

## 可复用的本地检查

`python scripts/check_title_transcription.py manifest.json`

manifest字段：`artifact:{path,sha256}`；`expected_ids`（从独立材料清单确定的本次正式标题范围）；`items`中每项为`id`、`paragraph_index`（所有w:p的零基索引）、`source_title`（不含附件编号）、`source_evidence:{path,sha256}`（真实标题原图/原页证据）、`source_locator`（页/位置）、`source_reviewed:true`、`review_note`（实际辨认说明）。仅适用于普通正文标题的可见w:t文本；修订、隐藏字、域、文本框等复杂表示拒绝自动放行，改按可见结果专项检查。

工具只读实际DOCX，不接受另一份“输出文字摘要”代替；检查文字、来源证据指纹及范围，并给出字符级差异。它不证明source_reviewed自述真实、不自动OCR原图、不替代独立材料清单或排版审核。返回`transcription_matches`只表示所列且已核实原文与实际文字一致；不能称全册名称正确，除非所列范围确实覆盖全册且原件核实已完成。

## 真实失败的抽象规则

- “水库”后补“水源地”、漏“集中式”、将“工程建议书”写成“工程项目建议书”：意思近似不等于同一正式名称。
- 漏“涉河”或把“意见的函”写成“意见”：改变事项/文种，不可作为正文简称。
- 复制旧转换稿仍会复制旧错误；“没主动改字”不能替代原件核实。
- 用户仅要求流程优化时，不擅自继续改文档。已发现错误的旧标题数据撤回正确性结论，媒体等不受影响资产不连带重做。
