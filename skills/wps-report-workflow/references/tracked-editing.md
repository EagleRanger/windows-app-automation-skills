# 真修订与精确回读

适用用户要求标记已修改内容的 DOCX。仅开启“跟踪修订”开关，不会给先前已改的文字补历史；彩色文字或删除线也不等于可接受/拒绝的修订。

## 稳定做法

1. 在另存副本前绑定源文件指纹、段落定位、修改前完整文字、核实后的文字、来源页和附件ID。修改范围不明确或旧字不匹配时停该项，不能全文模糊替换。
2. 尽量采用已测试的 DOCX 工具；需要 OOXML 时保留原 run 的 rPr（字体、字号、字重等），对确定差异建立 `w:del` 与 `w:ins`，记录唯一整数 w:id、作者和日期。删除文字使用 `w:delText`，新增使用 `w:t`。设置 settings.xml 中 `w:trackRevisions` 为 true。
3. 不把整段重写成统一字体；制表符、目录页码、手动换行、书签及媒体位置要保留。多段落/不同样式 run/域/文本框/旧修订不是普通字符串替换，无法安全处理就走专项适配，不静默压平。
4. 在中间位置添加换行，拆开原 run 并保留样式；用户要求所有修改留痕时，新增 w:br 也用插入修订包裹。不能为好看删字或改正式名称。年份不要拆开，顿号不要置于行首，长标题避免末字孤立。
5. 只有 document.xml 与明确需要的 settings/修订关系等部件允许变化；不重新压缩、重采样或替换原件图片。保存时先写唯一临时副本、验证后交付，不覆盖用户原稿。

## 双视图验收

- **交付修订稿**：结构确认存在插入/删除记录，ID不冲突、删除节点用 delText；WPS 实际打开并看到修订痕迹。包装器导出可能扩大纸面加入批注栏，这不代表 Word 原纸张已变大。
- **接受后的内部 QA 副本**：按记录仅接受本次修订，核实当前文字、目录、页码、断行和图像关系。交付稿仍保留修订，不能把 QA 清稿错发给用户。
- **拒绝回滚测试**：拒绝本次改动后，原有文字、原有修订及非目标格式应还原。存在用户旧修订时，不能无差别“全部接受/拒绝”。
- 同时校验实际文件字体/边距、媒体及非目标包部件保留，导出不是保存/编辑成功的替代证据。
- `documentProtection` 节点存在不一定启用保护，检查 enforcement；0/false/off 不是已锁定。不能因此擅自删除用户保护设置。

## 与原文检查器连接

`check_title_transcription.py` 对带修订的目标段落会拒绝自动放行。先从真实修订稿生成接受本次改动的内部副本，证明其每段文本与修订稿最终视图一致、拒绝后原文一致，再将该副本及指纹传给检查器；结果只证明指定原文一致，不替代真实修订显示和视觉检查。

材料分组/类别短名与正式题名分开计量。统计唯一错误附件条目，另列正文修改处数、目录同步处数、纯空格/换行；一条标题的三个漏字不能算成三个错误附件，修订节点数也不是错名数量。

## 已遇到的坑

- 目录看似一行，却由“文字 + 手动换行 + 文字 + 制表符 + 页码”组成；不能假定只有两个文字节点。
- WPS 返回成功但保存未生效：从文件字节、重开文字和导出效果确认。
- 只验证已接受副本，没有验证实际交付稿的增删节点：可能送出无修订文件。
- 加上修订后触发新断行或批注覆盖：带标记和最终视图都要看。
