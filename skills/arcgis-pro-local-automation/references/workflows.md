# 后台 ArcPy 与结果验收

## 通道不是一回事

前台插件控制用户可见工程；后台 ArcPy 操作显式路径上的文件。独立 Python 进程使用 `arcpy.mp.ArcGISProject(绝对APRX路径)`，不要使用只对 Pro 内部上下文有效的 `CURRENT`，也不要以为后台保存必然刷新前台窗口。

复用已安装的 Pro Python 或官方启动入口，不临时把系统 Python 指向另一个环境，不在任务中升级/重装 ArcGIS、修改全局 PATH 或下载一套未知运行时。所需分析授权由接收方合法配置；本 Skill 不查询、借出或归还扩展许可，也不绕过许可错误。

## 开始前固定

- 输入 APRX、地图/图层、数据集与字段；禁止靠同名图层猜目标。
- 真实工具名、完整参数、输出根和是否允许另存/覆盖。先检查工具是否存在，缺少的入口记为不可用，不声称调用失败。
- 输入与输出 CRS、米/度单位、像元大小、范围、snap raster、NoData 和数据年份。重采样为更细网格不等于提高原始数据分辨率。
- 原件保护、剩余磁盘空间与预计规模。不要同时让后台与前台覆盖同一 APRX/GDB。

后台可用工具由接收方安装和许可决定。历史实测包括坡度/坡向/晕渲、水文、邻域与分区统计、重分类、栅格代数、投影/裁切/重采样、转矢量和等高线等 36 个工具，不是任意工具都成功。前台 GP 白名单仍只有 Buffer/Clip。

## 一次操作的闭环

小样确认参数和坐标后再扩大范围；生成新输出，回读尺寸、范围、投影、数值/统计和 NoData。APRX 另存后重开并检查 broken sources。输出 PNG/PDF 后检查页面尺寸、DPI、图层可见性、图例、比例尺、文字、裁切和布局，实际看图才判断视觉通过。

原生崩溃留下工具、参数、输入和终止证据；在未找到可验证差异前不要原样重跑。超时/进程退出先查已生成文件与最后日志，把“未执行”“失败”“结果未知”“完成但未视觉验收”分开。

保存后返回：实际工程/输出、调用与回读结果、可恢复检查点、仍未验证的范围。没有成果时如实说明，不能用工具目录数量、进程存在或桥接成功替代结果。
