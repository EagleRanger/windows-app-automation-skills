# ArcGIS Pro 本地自动化操作与控制

以用户已打开的工程或明确提供的 APRX、输入数据和输出目录为对象。先确定目标及允许改动，再选择前台 AddIn 或后台 ArcPy；不因安装本 Skill 就获得修改工程、覆盖文件或上传数据的权限。

## 先选通道

- **前台地图、图层、视图和布局**：读 [连接与配置](references/setup.md)，使用 `scripts/bridge_client.py` 和内置 AddIn。插件基线是 Pro 3.4.3 / .NET 8 / Windows x64，34 个原生接口；前台 GP 只开放 Buffer、Clip。不是任意 ArcPy 代码执行器。
- **栅格、水文、批量分析或后台文件生成**：读 [后台与验收](references/workflows.md)，使用接收方合法安装的 ArcGIS Pro Python / ArcPy 和真实存在的工具。不要把插件白名单当成 ArcPy 全部能力，也不要把工具清单当实测通过数。
- 查能力与证据边界时读 [验证范围](references/validation.md)；需要构建或修改插件时，读 [构建方法](references/build.md) 及完整 `assets/addin-source/`。
- 已有试错经验见 [已踩过的坑](references/known-pitfalls.md)，不附通用排障流程；新 bug 由接收方自行处理。

## 操作要点

1. 不猜端口或当前工程。发现实例后以新鲜 `ping` 确认 PID，再用 `get_project_info` 确认工程绝对路径；多个实例不能自动选第一个。实例文件可能是退出进程留下的旧记录。
2. 默认只读。视图切换、图层更改、导出和保存同样属于有副作用操作；执行前固定 PID、工程、参数和输出。命令行的写入开关只是防误触，不替代用户授权。
3. 只用当前插件公开的命令与参数；通过 `--schema 命令名` 按需查看，不把完整 GP 参数表反复装入上下文。后台先确认工具实际存在、输入单位、投影、范围、NoData 和扩展许可由用户自行配置；不调用许可查询、借出、归还 API。
4. 一次发送对应一个请求 ID。超时、断线或响应错配是**结果未知**，先查回执、输出和当前工程，再决定如何恢复；不自动重发可能已生效的写入。原生崩溃也不原样反复重试。
5. 保留原件，默认新输出。`save_project(save_as_path=...)` 后当前工程可能已经切换，下一操作重新核对；不能认为原工程仍处于当前窗口。
6. 不用鼠标、键盘或抢焦点替代原生接口。没有对应能力就说明缺口；不暗中接入 Portal、下载运行时、改变 Python 环境或重装软件。

## 交付验收

区分：连接成功、命令返回、生成文件、保存重开、视觉正确。检查输出存在且可打开、工程可重开且数据源不损坏、布局尺寸/比例尺/文字/图例/裁切正确；图片和 PDF 必须实际看图。技术返回 PASS 不等于制图验收。

只保存必要的本地回执与恢复点；工程路径、聊天、账号、实例记录、原始地图与数据默认不离开本机。本 Skill 不包含 ArcGIS 软件、许可证或用户 GIS 数据。
